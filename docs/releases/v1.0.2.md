# overnight v1.0.2

Released 2026-09-08. Requires Python 3.9+, `pyyaml`, git and the Claude Code CLI
on the PATH. Install with `python install.py`; upgrade by pulling this checkout,
because the install is a link and not a copy.

## One attempt may now take several workers

A per-step money cap (`budget_usd`, overriding `run.budget_usd_per_step`) used to
mean a worker cut off mid-step was just a failed attempt, retried from a clean
tree. That wasted whatever it had already built. A worker cut off by its cap is
now **continued**: the next one gets a fresh budget and the tree exactly as the
last leg left it, plus a handover brief saying what is already built and not to
start over. The same money buys progress instead of repetition.

A worker that spent an entire cap and left the tree byte-identical is not a big
step, it is a runaway - continuing it would hand the next leg a half-built wrong
thing to finish. That trips the new outcome **`OVER BUDGET`** immediately, and so
does exhausting `run.continuations` (default 0, off). `OVER BUDGET` is blocking
(`--mode` reports the plan `BLOCKED`, the summary flags the step `<-- NEEDS YOU`)
and resumable - a resume picks it straight back up once the step is split or the
cap is raised.

The gates still decide: a worker that commits passing work and only then runs out
of money tidying up is still a `PASS`, because the budget trip is read before the
gates run and acted on only if they fail.

## What is now different for an existing plan

- **`OVER BUDGET` is a new blocking outcome.** A plan that used to march through a
  cut-off worker's retries now stops and asks for a person, exactly as `STUCK` and
  `HALTED` already do. Split the step or raise `budget_usd`/`run.budget_usd_per_step`,
  then resume.
- **`run.stall_min` defaults to 10 minutes and kills a silent worker.** A worker
  whose log stops growing - not slow, stopped - previously ran to
  `worker_timeout_min`, which has to be sized for the slowest legitimate step and
  so can never catch a stall early. Two real workers burned a full 90-minute
  timeout this way on 2026-09-07 before their retries passed in under an hour
  combined. Set `run.stall_min: 0` to disable if a step's own tools are expected
  to go quiet longer than that.
- **`expected_min` is now required on every build step still to run.** A plan
  with an unsized one is refused at load, naming every offending step. Steps that
  have already run are exempt. If a plan written before this release fails to
  load, add the missing estimates; nothing about a completed step's history
  changes.
- **The clock can now be a time of day.** `run.until` / `--until` sits beside
  `run.hours` / `--hours` and wins when both are given. Existing plans that only
  set `hours` are unaffected.

## Anything you may have quoted that was wrong

**The published self-test runtime was wrong by a factor of thirteen.** `README.md`,
`SKILL.md`, `CLAUDE.md` and the module docstring all said `python selftest.py`
finishes "in under a minute". Measured on 2026-09-07 it took 12-19 minutes over
235-292 checks - real subprocesses doing real git work, and it has grown with
every section added since that figure was first written. A wrong number is worse
than a bug here, because nobody goes looking for it: anyone who budgeted a minute
for the pre-launch gate was budgeting for the wrong thing. All four sites now
carry the measured figure, and a run ends with a table of where its own time
went so nobody has to take a documented number on trust again.

## Also

- **The self-test runs in pieces.** `--list` names the sections, what each needs
  first and how many checks it makes; `--only 13,17` and `--from 17` run part of
  the suite and print `SELFTEST PARTIAL OK`, never `SELFTEST PASS`, so a partial
  run cannot be mistaken for the gate a launch is checked against. Every section
  now declares its check count, and the suite fails loudly if a section's count
  changes - a check silently dropped otherwise still ends in `SELFTEST PASS`.
- **Work stranded on a scratch branch by a crashed run is retested, not just
  reported.** Before a build step runs, if its scratch branch already holds
  passing, uncommitted-elsewhere work from an earlier run, the runner replays it
  onto the current base and runs that step's own gates against it. Passing work
  merges with no worker spawned; failing work is tagged and discarded exactly as
  before. Recovered an $5.12, 11-minute step for free on the run that motivated it.
- **A circuit breaker for the usage wall.** Three workers in a row that return
  nothing at all (`run.wall_threshold`) means the account can't succeed right
  now, not that the plan is bad. The run records the step `NOT RUN` and, by
  default, parks - probing every 30 minutes (`run.park_poll_min`) until the
  account answers, then resuming where it left off. Parked time never extends
  the stop time.
- **`/overnight plan <path>` can now seed from a document you already wrote** - a
  roadmap, an issue list, `DECISIONS-PENDING.md` - and interviews only on what it
  didn't answer. The planner must list anything it dropped, merged or split, at
  the top of its proposal: a seed that is silently filtered is worse than no
  seed.
- **`tools/progress.py <project dir>`** prints one line per project - live or
  not, current step, how far through the plan, what it has spent - for the
  question asked at 3am. Read-only, safe against a run in flight.
- Fixed: a leftover worktree registration on Windows (path comparison used raw
  string equality against forward-slash `git worktree list` output) could delete
  every live worktree and strand a step at zero attempts. Fixed: a worker's
  output containing a character the launching console can't encode no longer
  kills the run after the worker has already committed. Fixed: a worker woken by
  its own backgrounded task was undercounted - `tools/tally.py` now reconciles
  exactly with the CLI's reported cost.

Full detail in `CHANGELOG.md`.

## Upgrading

    git pull
    python install.py --check     # confirm the skill still points at this checkout
    python selftest.py            # must print SELFTEST PASS before any launch

The install is a directory junction (Windows) or a symlink (elsewhere), so a pull
is the upgrade. If `--check` reports "a real directory", something replaced the
link with a copy at some point and your fixes were not reaching the skill:
`python install.py --force` repairs it.
